**Database proof:** pin Prisma `6.19.3` native engine `c2990dca591cba766e3b7ef5d9e8a84796e47ab7`, deployment Linux image and CA fingerprint. Use a private DNS endpoint, require TLS and strict certificate acceptance. Validate the CA path and hostname behavior using the actual engine rather than assuming libpq parameters work. Test trusted CA + correct SAN success, wrong CA, trusted CA + wrong SAN, expired certificate and plaintext-only denial, plus rotation and reconnect. Verify negotiated TLS, DML-only role and no public reachability. `pg_stat_ssl`, `openssl` and `psql` are supporting observations. None establishes Prisma hostname verification by itself. [Pinned engine evidence](CLOUD_03B_EVIDENCE.md) · [Prisma v6 connector](https://www.prisma.io/docs/orm/v6/overview/databases/postgresql)

Review written retention, default domain behavior, incident/support capture, DPA/subprocessors, deletion and tradeoffs on the exact plan. No split Web/API provider is budgeted because it adds a second trust and logging boundary with no benefit to the static or same-origin baseline. AWS TCP design is the fallback only after testing, or the first private candidate if the managed edge cannot meet logging requirements. No candidate passes private acceptance on documentation alone.

## 30-day planning model (USD)

One environment, 720 hours, no production resources or credits assumed. Showroom estimates use one replica per process/DB and are not HA, SLA or a signed quote. Demo traffic assumptions:

| Band | Public preview | Private runtime |
| --- | --- | --- |
| Base | 1,000 visits, 10,000 asset requests, 2 GB outbound | 10 guided demos, 10 GB outbound, 5 GB sanitized log ingest/retention allocation |
| Meetings | 5,000 visits, 100,000 requests, 20 GB outbound | 50 demos, 50 GB outbound, 10 GB sanitized observability allocation, one restore rehearsal |
| Burst | 25,000 visits, 500,000 requests, 100 GB outbound | 150 demos, 150 GB outbound, 20 GB sanitized observability allocation, temporary restore/scale capacity |

**Public Track A, standalone cost.** Render Pro $25 per workspace, static compute $0, 25 GB included bandwidth then $0.15/GB, one custom hostname within included count. Plan allowances of $2 for a domain amortization and $3/5/10 for monitoring produce **$30/$32/$48.25** across bands. Confirm bandwidth accounting and build minutes. A commercial use and support selection may later qualify for another plan. AWS alternative CloudFront Pro $15 per distribution includes published allocations of 10M requests and 50 TB transfer, with optional attached DNS and storage credits. Reserve another $5/7/12 for domain amortization, object operations and independent probes for **$20/$22/$27**. Verify credits/eligibility and artifact size before approval. Railway Pro modeling at $20 minimum with low static service usage inside included credit, plus $2 domain and $3/5/10 probes, gives **$25/$27/$32**. At 100 GB Railway outbound alone is $5; assume the small static service keeps compute plus traffic below $20 and reprice if it does not. DB, backup, runtime credentials and application workspace access are absent for this track. **Founder choices:** propose an all-in **$60/30 days** ceiling for Track A and a later **$200/30 days managed / $300 AWS** ceiling for a separately authorized private evaluation, including contingency for quoted cost and tax. If both are approved, budget them additively. The first private test month includes a restore exercise. Configure spend alerts (50%, 75%, 90%), admission/egress quotas, a named owner and a day-30 stop review. Budget alerts can lag and cannot guarantee a cap. Reject any plan that cannot support required controls within the approved quote and operating burden. Start with the lowest-complexity qualifying scope, the static preview, and keep private Track B blocked until evidence and explicit approval are complete.
