## A · Public preview

Publish only a separately built static artifact at a distinct hostname, for example `preview.example.invalid`. The QR contains its ordinary public HTTPS URL. Show clearly labeled illustrations and interactive, fixed synthetic examples of the guest request and hotel response. Use no account form, free-text collection, cookies, analytics, embeds, operational metrics presented as real, service worker or backend. Package assets locally. Limit CSP to required first-party assets and disable connections and form submissions. Check that browser network traffic reaches only the approved static asset host. CI should verify the artifact allowlist and absence of operational routes, server rewrites, source maps, credentials and real records. Review headers, TLS, privacy and accessibility on a separate release. A stable QR can also serve as the meeting fallback if the guided interactive path is unavailable.

```text
Laptop / phone → public DNS + managed HTTPS/CDN → static artifact
  / and versioned bundled assets                  only
  /api/*, /socket.io/*, /connect and /connect/*    absent, return 404
```

Ship an independent build rather than the operational Next artifact with routes hidden in the UI. Cache only versioned public assets. Revert by restoring the previous verified static artifact, invalidating replaced HTML and checking the same QR. Render Static Sites is the proposed first candidate. CloudFront with private S3 Origin Access Control is an alternative for AWS standardization. [Render static sites](https://render.com/docs/static-sites) · [AWS private S3 origin](https://docs.aws.amazon.com/AmazonCloudFront/latest/DeveloperGuide/private-content-restricting-access-to-s3.html)

## B · Private synthetic Showroom

“Private” means application access limited to invited viewers and operators over a reachable HTTPS gateway. Hotel Wi-Fi and cellular browsers need no VPN. Next, Nest and PostgreSQL have no directly reachable public origin. Provision a new synthetic environment only after approval. Separate Showroom from any existing evaluation environment and prospective production using distinct projects/accounts, networks, domains, credentials, DBs, backups and release roles. Never copy Pilot 01, use tunnels or connect to the Mac mini.

```text
Browser → approved DNS → HTTPS/WSS entry → trusted gateway → private Next :3000
                              │                         └─→ private Nest :3001
AWS fallback: TCP:443 NLB ────┘                             │ verified TLS
          first HTTP receiver is owned gateway             └─→ private PostgreSQL
```

For AWS the NLB passes encrypted TCP to the gateway. Terminate TLS there with a DNS-validated certificate, automate least-privilege DNS renewal and alert before expiry. Use two public NLB subnets and private task/DB subnets, with TLS SNI/Host allowlist, TCP health check plus independent application health. Put no HTTP CDN, ALB, platform proxy or WAF before that termination. Railway has a managed TLS edge before the gateway. That alternative requires separate first-hop proof. Use approved DNS, certificate renewal and expiry alerts, reject default hosts, enforce HTTPS/WSS and fail closed on unknown paths. Keep same-origin cookies and preserve Origin and Upgrade. The gateway strips spoofable forwarding headers, never derives tenant authority from a header, and does not upgrade a client-controlled tenant identifier into authorization.

| Path | Proposed owner and policy |
| --- | --- |
| `/`, login and versioned Web assets | Private Next. Founder/operators enter through an individually authenticated staff admission path. Default deny other pages. No shared caching of authenticated or guest responses. |
| `/api/*` | Explicit route/method allowlist to private Nest preserving prefix. Expose only reviewed login/session, demo operational reads/writes and guest exchange/stay/requests/logout. Deny legacy issuance and all legacy reads/writes in both the gateway and application, along with signup, billing and unused routes. Operator issuance is scoped and uses a separately approved surface. |
| `/socket.io/*` | Private Nest, Upgrade and cookies preserved, exact Origin, namespace `/realtime`. Start with one replica and a bounded idle timeout above Engine.IO heartbeat. Test reconnect, auth refresh and revocation. |
| `/connect` and future `/invite` | Only canonical token-free shells with CSP, no-store and no-referrer. Reject token/query variants without redirects. A first-HTTP-hop denial must also avoid recording the rejected input. |
| Health | Private readiness, sanitized external probe if needed. `/api/health` proves Nest responds, while DB and session checks are separate. |

A visitor participates **as one guest**, never as hotel operator, with one synthetic reservation and the ability to see their own stay/history and make a small number of approved synthetic requests. Prefer prewritten choices to avoid collecting personal details. A named founder/operator uses a separate, MFA-protected staff session with minimum necessary request and notification privileges. Bootstrap issuance needs separate narrowly scoped authority because the current permission covers reservation management. Hotel B is a distinct operator profile and a negative test tenant. Use explicit least-privilege permission design before implementing a new role. Grant no owner, booking, billing, tenant switch, exports or platform administration to prospects. Staff and guest cookies remain distinct, host-only, Secure and HttpOnly. Gate writes on expected Origin, CSRF, live reservation and role/session authorization. Cap attempts per source and per verified session/tenant, handle shared hotel NAT, limit body sizes and concurrent sockets and measure 429/retry behavior. Start with five pooled DB connections plus reserve for migration/backup. No public DB IP, unrestricted task egress or cross-tenant caches.

Founder issues the QR for a specific agreed demo, showing only to the intended visitor. Use a one-use fragment code and explicit exchange with short TTL, revocation and bounded abuse. Keep QR images out of screenshots, chat, clipboard managers, logs, support attachments and archives. URL fragments are omitted by normal HTTP requests but capture before cleanup can occur in the browser, QR scanner or link-sharing tool. Cookie/POST capture remains an ingress risk. For stronger recipient binding, use a separately delivered one-use challenge or operator approval. A QR is bearer possession, not identity proof. Suggested demo admission: one meeting, 5-minute code issuance near scan, two-device cap for the Showroom and 60-minute absolute/15-minute idle viewer session, subject to founder review. Never copy the local CI gate or change production mode to development. Design a reviewed environment-specific gate, isolated fixture provisioner, revocation/reissue policy and scoped issuance first. A real trial invitation under #38 is separate from demo guest access.

Preflight phone Safari and Chrome on Wi-Fi and cellular, scan with native camera, validate certificate, CSP, cookie and reconnect. If a captive portal, clock, hardware/browser compatibility, outage or rate limit interrupts the meeting, present the public mock and resume a private demo after recovery. Use persisted Notifications after socket failure. Single replicas can interrupt reconnects and scheduled updates. Multiple replicas require a shared rate limiter, Socket.IO adapter and reviewed revocation/drain semantics. Keep DML-only runtime, one-shot DDL migration identity, separate backup identity and least-privilege secrets. Allow egress only for necessary registry/log/secret endpoints and certificate operations. Keep guest request bodies, cookies and capability credentials out of traces and crash dumps. ## Legacy capability inventory and threat model

| Exposure / actor | Current surface and impact | Candidate mitigation |
| --- | --- | --- |
| Staff issuer or stolen staff session | POST `/api/connect-admin/reservations/:reservationId/access` returns raw token, path and expiry after session/tenant/`reservations.manage` checks. Reservations UI constructs the URL, displays it and may copy it. Reissue rotates the hash. DELETE on that route revokes. Guest and staff authorizations differ. | Deny legacy issuance and delivery on Showroom ingress and in Nest. Preserve original local routes and existing links elsewhere. Restrict new bootstrap to audited permission and exact scope. [Admin controller](../../apps/api/src/connect/connect-admin.controller.ts) · [Reservations UI](../../apps/web/src/app/reservations-center.tsx) |
| Anyone holding original URL | `/connect/[token]` in Next, GET `/api/connect/:token` for stay/history polling, POST `/api/connect/:token/requests` for scoped writes. The hash is persisted. Reads can continue after checkout until access expiry/revocation. In-flight writes can race legacy revocation. | Inventory active counts and expiry by environment with hashes/IDs omitted. Reject normalized/encoded path variants before forwarding. A redirect, shortening or downstream Nginx redaction happens after exposure. No migration, rotation or revocation as part of this decision. [Guest page](../../apps/web/src/app/connect/[token]/page.tsx) · [Legacy controller](../../apps/api/src/connect/connect.controller.ts) · [Connect service](../../apps/api/src/connect/connect.service.ts) |
| Edge, operator or vendor support with log access | TLS termination, CDN/WAF, reverse proxy, host or default-domain errors, 404/redirect/rate-limit handling and WSS upgrades can capture the raw request target before local redaction. Response logs can capture issuance JSON or Set-Cookie. APM, drains, Prisma error context, session replay and support tooling can retain headers/body. | Select before-persistence omission at the first receiver or owned first TLS termination. Verify access/error/security/sampled/observability/exports and support-visible storage for synthetic non-secret canaries in path/query/body/headers/Set-Cookie, including encode/error/deny paths. Disable request payload telemetry and preserve only route category/status, aggregate latency and random trace ID. Disabling a log UI or drain is insufficient. [Phase A log tests](../../infra/staging/README.md) |
| Browser, scanner, recipient or third party | Legacy URL resides in address bar/history, copied URLs, QR, link previews, referrer, screenshots, HAR, support tickets and clipboard sync. Current no-referrer/no-store and Next dev access-log filtering reduce particular sinks. | Preserve legacy on isolated local Pilot. Use fragment cleanup before network requests and forbid query/path fallbacks, third-party assets and analytics. Disable scanner sharing/history where possible. Train operators to report only sanitized result codes. [Browser shell](../security/CONNECT_SEC_04_BROWSER.md) · [Mac mini runbook](../PILOT_01_MAC_MINI.md) |
| Backup/restore operator or retained artifacts | DB hash-only storage does not prevent usable old capabilities after restoring older generations or sessions. Plaintext can survive in gateway logs, APM snapshots, screenshots and external exports even if the DB stores only hashes. | Restore isolated before access; revoke recovered generations/sessions/invites and prove denial before reopening. Encrypt backup/storage, prune logs/drains/support artifacts with confirmed retention. Report leaked credentials through private incident handling and rotate at the issuer. [Recovery plan](CLOUD_01_ACTIVATION_AND_GATES.md) |

Fixed paths remove tokens from legitimate guest HTTP request targets, potentially making a managed edge viable. They do not remove legacy route exposure in main, protect new codes/cookies from body/header capture, or prevent a forwarded old URL from appearing on a new edge's rejected request log. A candidate with path capture needs positive evidence covering rejected/default-domain traffic or an approved design that keeps every still-valid legacy bearer outside its disclosure boundary with a rehearsed inventory and migration strategy. Main's new shell and API only work in their local synthetic harness. A selected provider does not change this gate.

## Sequence and operator ownership

1. Founder reviews budget, preview labeling and hosts, roles, policy, region, visibility and the free-of-customer-data boundary. Name a release owner and backup for ops/security/data/support. Approve a separate static artifact PR, then any actual preview release separately.
2. Submit separate protocol/policy and synthetic provisioning PRs. Default deny all legacy routes in the hosted program. Pin binaries, validate least privilege, private routing, account isolation and first-hop controls. Treat a missing viable provider within the ceiling as a stop, using Track A for sales.
3. Only under separate authorization, build disposable synthetic provider proof. Rehearse TLS/CA rotation, log canaries, private negative reachability and expiry. Collect paid plan, region, support, retention and total-cost evidence while access is restricted. Approve WSS and rate limits before moving to meetings.
4. Rehearse day-of operation with two synthetic hotels, sanitized monitors and incident triage. Probe health and DB, WSS and backup freshness. Proposed retention: metadata-only diagnostics 7 days, synthetic workspace 30 days, encrypted daily exports 30 days with restricted restoration. Page a named operator after two failed probes; fence writes/revoke viewer admission if integrity or privacy is uncertain. Roll back compatible gateway/API/Web artifacts together, preserve revocations and history, and fall back to static. Review a measured restore and deletion drill before any viewer access.
5. Release private Showroom only after evidence and founder sign-off. Production and real data require a separate decision, #38 delivery and privacy/legal/support approval. Keep local Pilot unaffected.

## Public repository hygiene

Founder intent is public per #59. At the audited SHA, GitHub returned public visibility. The read-only scan walked all 40 commits reachable from that SHA on GitHub, enumerated their untruncated trees and checked 453 distinct text blobs. Patterns covered PEM private keys, common provider/API token prefixes, credential-shaped URLs, quoted secret assignments and literal legacy capability paths. The 35 candidate occurrences across 24 blob revisions resolved to test inputs, disposable CI configuration or sample configuration by context. No confirmed real secret surfaced in that scope. Treat sample defaults as examples and never reuse them. No raw candidate values were emitted as evidence.

This is a bounded pattern scan of tracked main history. It does not attest unmerged/deleted refs, GitHub releases/artifacts, actions logs, issues/comments, external caches, fork history or unknown secret formats. Founder/security should independently scan those surfaces and confirm visibility before sharing. If a real credential is found, privately identify the path/commit and provider, revoke/rotate first, review usage and invalidate sessions/capabilities as relevant. Follow the reviewed GitHub cleanup process for retained history, forks and caches. No visibility change or history rewrite is proposed here. [GitHub sensitive data removal](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/removing-sensitive-data-from-a-repository)
